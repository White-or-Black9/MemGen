# MAB-5C: detective_qa Decoupled Retrieval-Update Thresholds n10

## Purpose
Test whether separating retrieval visibility from write-back matching can keep MAB-5A-like retrieval density while preserving MAB-5B-like slot growth.

## Settings
- Split: `Long_Range_Understanding`
- Subtask: `detective_qa`
- Contexts: 10 local rows
- threshold: `0.03`
- retrieve_threshold: `0.03`
- update_threshold: `0.05`
- top_k: `1`
- max_slots: `8`
- retrieve_policy: `threshold_topk`
- update_policy: `thread_update`
- query mode: first-query-only
- query phase: read-only
- full-history detective_qa: `over_capacity_invalid`

## Protocol Notes
- Shared-threshold behavior remains the default when both split thresholds are `None`.
- Retrieval visibility uses `retrieve_threshold`.
- Write-back matching uses `update_threshold`.
- Retrieved memory stays Reasoner-only and does not enter Weaver.
- No fallback mechanism was introduced.
